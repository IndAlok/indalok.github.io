EPEL paper, the study this project builds on

Open paper

What it is

Bi and co-workers, "Ensemble learning-based predictor for driver synonymous mutation with sequence representation", PLOS Computational Biology, 2025. EPEL is the current best predictor of which synonymous (silent) mutations drive cancer.

How it connects to our project

  • Our dataset is EPEL's dataset, taken exactly as published. Nothing is re-collected or re-labelled by us.
  • EPEL is also the baseline. It encodes DNA with EIIP values and combines five tree models (CatBoost, random forest, gradient boosting, AdaBoost, XGBoost) with logistic regression stacking.
  • Our project changes one thing only: the features. We test whether FFT period-3 spectral features do better, per mutation class.
  • We checked the full text of the paper: FFT, Fourier and spectral methods appear zero times. That gap is our project.

What to demonstrate

  • Show the title page and abstract.
  • Point at the reported performance: independent test AUC about 0.86 and AUPR about 0.88.
Say: "This is the paper we build on. We use its data as it is, and we test the one thing it never tried, the frequency spectrum of the sequence."

EPEL GitHub repository, where our dataset lives

Open repository

What it is

The authors' official public repository: source code, trained models, the data files and the published prediction scores. Public, no login, no access request.

How it is our dataset source

  • The data folder holds the two variant list files we use, shown in cards 3 and 4.
  • The README states the data is COSMIC and describes the five-model ensemble, matching the paper.
  • The out/ulti_data folder holds EPEL's own scores for the test set (test_score.vcf), which we can compare our scores against.
  • Because the source is public, every number in our project can be checked by anyone from this page.

What to demonstrate

  • Scroll the README: the data line and the model description.
  • Open the data folder and show the two files with their sizes, about 92 KB (train) and 24 KB (test).
Say: "Our dataset is not a private copy. It is these two files in the authors' own repository, and anyone can download them and repeat our counts."

Test dataset: id_test_close7.txt

Open file

What it is

EPEL's independent test list, derived from COSMIC v95. 998 synonymous variants plus a header row, balanced 499 positive and 499 negative.

Format, column by column

  • chr and pos: chromosome and position on hg19 (GRCh37).
  • ref and alt: the reference base and the mutated base.
  • Gene name: the gene the variant sits in.
  • Last column, the label: 1 means the variant appeared in at least 7 tumours in COSMIC v95 (recurrence r ≥ 7, likely driver). 0 means it appeared exactly once (r = 1, likely passenger). EPEL paired each driver with a nearby passenger and removed near-duplicate sequences, which is why the set is balanced.

How it is our dataset

  • This is our held-out test set for the direct comparison with EPEL (scheme S1).
  • Our own check on this public file: 152 of its genes also appear in the training list, covering 331 of these 998 rows. Our corrected test set (scheme S2) removes those rows, leaving 667. Our main result (scheme S3) re-splits all 4,824 variants so no gene appears on both sides.

What to demonstrate

  • Read the header row, then one positive C to T row aloud: chr 5, position 43,245,922, C to T, gene NIM1K, label 1.
  • Read one more famous one: chr 14, position 105,239,894, C to T, gene AKT1, label 1.
  • Read one negative row: chr 2, position 44,153,083, A to T, gene LRPPRC, label 0.
  • Scroll through the file to show the volume, and point out how many rows are C to T changes.
Say: "Every line is one silent mutation with its label. The labels are tumour counts from COSMIC, turned into 1 and 0 by EPEL's rule. This file is our test set."

Training dataset: id_train_close7.txt

Open file

What it is

EPEL's training list, same source (COSMIC v95) and same format as the test file. 3,826 synonymous variants plus a header row, balanced 1,913 positive and 1,913 negative.

How it is our dataset

  • Together with the test file this is our complete dataset: 4,824 labelled variants.
  • The training list covers 1,583 genes, the test list 487 genes.
  • Across both files, 2,699 of the 4,824 variants are C to T changes, the class our project focuses on, because the EIIP encoding can barely see it (C and T differ by only 0.0005 in EIIP value).
  • In our main evaluation (scheme S3) both files are pooled and split by gene, so a gene is never in training and test at the same time.

What to demonstrate

  • Open the file and show the columns are identical to the test file.
  • Show the file size and length, no need to read rows here.
Say: "Same format, the training half. Train plus test is 4,824 labelled variants, and that is the entire dataset of this project."

One variant in the genome: UCSC Genome Browser

Open browser view

What it is

One actual row of the test file, shown in the UCSC Genome Browser on hg19: chromosome 17, position 41,245,466, G to A, in the gene BRCA1, label 1. The view is exactly 101 bases wide (chr17:41,245,416 to 41,245,516), centred on the variant.

How it connects to our dataset

  • Every row of the two files becomes exactly this: one position in the hg19 genome, one reference base, one gene.
  • Our pipeline cuts this 101 base window out of the reference genome for every variant, encodes it three ways (EIIP, Voss, Z-curve) for the reference and the mutated base, and runs the FFT.
  • The window is 101 bases because that is EPEL's window, so the comparison changes only the features, not the input.

What to demonstrate

  • Point at the centre of the window: the variant position and the reference base G.
  • Zoom out once to show the BRCA1 gene around the position.
  • Point out the assembly is hg19 (Feb 2009, GRCh37), the same build as the dataset coordinates.
Say: "This is what one data point actually is. A single letter in the genome, in a known cancer gene, and the 101 bases around it are the exact input to our method."

COSMIC, where the labels come from

Open COSMIC

What it is

The Catalogue of Somatic Mutations in Cancer, maintained by the Wellcome Sanger Institute. It is the largest curated record of mutations found in human tumours. EPEL used COSMIC version 95.

How it is our dataset's origin

  • Our labels are not invented or simulated. Each label is a count of real tumours in COSMIC v95 that carry that synonymous variant.
  • EPEL's labelling rule on those counts: recurrence at least 7 becomes label 1, recurrence exactly 1 becomes label 0, and each positive was paired with a nearby negative.
  • Full COSMIC downloads need a free registration, and the download page lists recent releases. We do not need them, because EPEL published the exact v95-derived lists on GitHub (cards 3 and 4).

What to demonstrate

  • Search for AKT1 in the COSMIC search box and show the gene page with its recorded mutations.
  • If asked, open the downloads page and show that datasets are distributed per release.
Say: "The labels start here. A variant seen in seven or more tumours is our positive, a variant seen once is our negative. Real tumour data, counted by EPEL from COSMIC v95."

hg19 reference genome: UCSC downloads

Open downloads page

What it is

The UCSC download server. The human reference genome for the GRCh37 (hg19) build is the file hg19.fa.gz, in the folder goldenPath/hg19/bigZips, about 900 MB compressed.

How it is our dataset

  • The two variant lists give only positions and base changes. The actual DNA letters come from this one file.
  • Our pipeline downloads it once and cuts the 101 base window around each of the 4,824 variants from it.
  • Hard rule of the project: everything stays on hg19. Mixing in hg38 coordinates would silently shift positions and break the codon phase, so no other build is used anywhere.

What to demonstrate

  • Show the Feb 2009 (GRCh37/hg19) section of the downloads page.
  • Do not start the download during the meeting, the file is about 900 MB.
Say: "The lists give positions, this file gives the letters. Every window we analyse is cut from this single reference genome, hg19 only."

GENCODE, GRCh37-mapped releases (50lift37)

Open GENCODE page

What it is

GENCODE is the reference gene annotation for the human genome. This page lists the releases mapped back to the older GRCh37 build. Release 50 appears in the table as 50lift37, which is the version we use.

How it is our dataset

  • From this annotation we take, for every variant: which gene it is in, which strand the gene is on, and the codon phase of the position.
  • The strand matters directly to our question: a C to T change is only counted on the gene's coding strand, because the same change read on the other strand is a G to A.
  • When a variant overlaps several transcripts, we pick one in a fixed order: MANE first, then canonical, then APPRIS, then the longest coding sequence.

What to demonstrate

  • Show the table on this page and point at the release 50 row, marked 50lift37.
  • That is the last of the four data sources. The dataset is now fully shown.
Say: "And the annotation comes from GENCODE 50lift37. It tells us the gene, the strand and the codon position for every variant, which the encoding step depends on."

If asked about the gene overlap

We compared the gene name columns of the two public files on cards 3 and 4. 152 gene names appear in both files, and they cover 331 of the 998 test rows. EPEL's paper does not discuss this. Our evaluation handles it three ways: the original split for comparability (S1), the test set with those 331 rows removed, 667 left (S2), and a gene-grouped split of all 4,824 variants as the main result (S3), plus a chromosome hold-out stress test (S4).

The dataset in one line: COSMIC v95 tumour counts, turned into labels by EPEL and published on GitHub, windows cut from the hg19 reference genome (UCSC), gene, strand and codon phase from GENCODE 50lift37. Total 4,824 labelled synonymous variants. Every source is public and free.
